## (a) Envelope encryption

```
┌─────────────────────────────────────────────────────────┐
│ Per-persona DEK (AES-256-GCM, 256-bit, random per       │
│ persona at creation)                                    │
│ Rotation: on-demand (via KMS re-wrap, no data re-       │
│ encrypt needed)                                         │
└─────────────────────────────────────────────────────────┘
                         │ wraps via AES-KEYWRAP (RFC 3394)
                         ▼
┌─────────────────────────────────────────────────────────┐
│ Per-tenant CMK (Customer Master Key, held in cloud KMS) │
│ AWS KMS: symmetric AES-256 CMK, KeyUsage=ENCRYPT_DECRYPT│
│ GCP Cloud KMS: AES-256-GCM symmetric key               │
│ Azure Key Vault: RSA-HSM (2048) or AES (256) CMK       │
│ Rotation: automatic annual + on-demand                 │
└─────────────────────────────────────────────────────────┘
                         │ protected by
                         ▼
┌─────────────────────────────────────────────────────────┐
│ HSM-backed root of trust (FIPS 140-2 Level 3)           │
│ AWS CloudHSM, GCP Cloud HSM, Azure Dedicated HSM        │
│ OR on-prem HSM (Thales Luna, nCipher nShield) for       │
│ self-hosted deployments                                 │
└─────────────────────────────────────────────────────────┘
```

**Per-persona DEK benefits:**
- Enables H-137 per-persona crypto-shredding (destroy one DEK; other personas unaffected).
- Enables per-tenant CMK rotation without data re-encryption (re-wrap DEK only).
- Compartmentalizes compromise: leak of one DEK affects one persona.
- Scales: N personas × 256 bits ≈ 32 bytes/persona = negligible storage overhead.

## (b) TLS 1.3 in-transit

**Configuration:**
- TLS 1.3 MANDATORY (no TLS 1.2 fallback; per RFC 8446 + NIST SP 800-52 Rev. 2 recommendations).
- Cipher suites: `TLS_AES_256_GCM_SHA384`, `TLS_AES_128_GCM_SHA256`, `TLS_CHACHA20_POLY1305_SHA256`.
- Certificate pinning for LLM-provider endpoints (OpenAI, Anthropic, Mistral).
- mTLS between internal services (storage ↔ extractor ↔ planner ↔ answer).
- HSTS header: `max-age=31536000; includeSubDomains; preload`.
- Forward secrecy via ECDHE-only key-exchange (X25519 preferred).

**Rationale:**
- TLS 1.2 has known weaknesses (Downgrade attacks, Bleichenbacher, Lucky Thirteen historical).
- TLS 1.3 mandatory provides post-Snowden + Schrems II compliance posture.
- NIST SP 800-52 Rev. 2 "Guidelines for the Selection, Configuration, and Use of Transport Layer Security (TLS) Implementations" (Aug 2019) recommends TLS 1.3 and the listed cipher suites.
- PCI-DSS v4.0 (2024) requires TLS 1.2+ (1.3 preferred); HIPAA covered-entity guidance aligns.

## (c) Regional deployment pinning (per H-136)

Each tenant configured at onboarding with:

```yaml
tenant_region: "eu-central-1"   # or us-east-1, uk-south-1, ap-southeast-1, ...
storage_region: "eu-central-1"  # must match or be within tenant_region
kms_region: "eu-central-1"      # MUST match storage_region (co-located)
llm_endpoints:
  primary: "openai-eu-frankfurt"    # OpenAI EU endpoint
  secondary: "anthropic-aws-bedrock-eu"  # Anthropic via AWS Bedrock EU
  detection: "prompt-guard-local-vm"    # self-hosted OSS detector (H-128b)
```

**Routing enforcement:**
- Storage driver rejects writes with `tenant_region != row_region`.
- LLM client refuses calls to out-of-region endpoints.
- KMS CMK is region-pinned by KMS provider (cannot be replicated cross-region without
  explicit KMS key-replica configuration).

**LLM provider regional endpoints verified (as of 2026):**
- **OpenAI:** US (global), EU (Frankfurt), UK endpoint for OpenAI Direct.
- **Anthropic:** US (via API + AWS Bedrock); EU via AWS Bedrock eu-central-1, eu-west-2.
- **Mistral:** EU-native (La Plaine-Saint-Denis, Paris).
- **Google (Gemini):** US, EU (multiple regions), APAC.
- **Azure OpenAI:** US, EU (Sweden, Ireland, Netherlands), UK, APAC.

All major providers offer regional endpoints. Residency compliant.

## (d) Backup inheritance

- Postgres physical backups (pg_basebackup / pgBackRest / WAL archives): stored with same
  per-persona DEK-wrapping; operationally the tablespace pages are ciphertext at rest, so
  backups are ciphertext by construction.
- SQLite-per-persona (T-020 alternative): file is AES-256-GCM-encrypted; backup copies the
  encrypted file verbatim.
- Snapshot (H-131 SLI-6 WAL lag metric): stored in S3/GCS with SSE-KMS using same per-tenant
  CMK; regional bucket pinned.
- Disaster-recovery replica: DEK replicated to replica region IF and only IF KMS is
  configured with explicit cross-region key-replica (not default). Default = no cross-region
  replication → no off-region copies.

**Key property:** crypto-shredding (H-137) propagates structurally. Destroy the DEK →
ciphertext in ALL backups/snapshots/replicas is unreadable simultaneously.

## (e) KMS audit log feed to H-131 SLI-12

KMS operations logged:
- `Encrypt` / `Decrypt` calls (per DEK wrap/unwrap operation).
- `GenerateDataKey` (new persona DEK creation).
- `ScheduleKeyDeletion` / `CancelKeyDeletion` / `DisableKey` / `EnableKey`.
- `UpdateKeyPolicy` (CMK policy changes).
- Failed auth attempts.

**AWS CloudTrail / GCP Cloud Audit Logs / Azure Activity Log** captures each operation with
actor, resource, timestamp, source IP. Events streamed via OTel Collector into Prometheus

Per-tenant audit log exposed via DSAR (H-136 Art. 15) on request.

## Per-persona granularity under T-019 / T-020

- **T-019 (Postgres JSONB):** persona_id is a primary shard key; DEK is applied at the
  application layer via `pgcrypto` or application-level envelope encryption before row
  insert. Alternative: transparent data encryption (TDE) via Postgres extensions — but TDE
  is typically per-tablespace, not per-row, so **application-level envelope encryption is
  load-bearing for per-persona granularity.**
- **T-020 (SQLite-per-persona):** per-persona file is inherently per-persona; SQLite +
  SQLCipher extension provides file-level AES-256 with the DEK supplied at open-time.
  Per-persona granularity is natural.

## On-prem HSM alternative

For self-hosted / air-gapped deployments:

```yaml
kms_provider: "thales_luna_hsm"   # or "ncipher_nshield", "securosys_cloudshsm"
kms_endpoint: "hsm.internal.corp:50078"
tenant_cmk: "tenant_ABC_cmk_label_v1"
fips_level: 3
```

HSM replaces cloud KMS; API contract is identical (wrap/unwrap/rotate/destroy). Architecture
unchanged.
