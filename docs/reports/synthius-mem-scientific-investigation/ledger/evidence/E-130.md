## Findings

### (a) 99.55% context definition

Quoted from §4.4 page 20:

> **Adversarial robustness (99.55%).** Of 442 false-premise questions, only 2 were answered
> incorrectly — the system correctly refused or hedged on the rest. This near-perfect score is
> a structural consequence of the extraction architecture: the knowledge base contains only
> attested facts, so when the retrieval tools return no supporting evidence for a premise, the
> absence itself is a reliable signal for refusal.

Arithmetic recompute: 440/442 = 99.5475% → 99.55%. Canonical.

§4.1 category-5 definition (page 13):

> **Adversarial**: False-premise questions containing incorrect presuppositions, designed to
> test whether the system detects unsupported premises rather than hallucinating a plausible
> response.

§4.1 knowledge-type category (page 14):

> **Adversarial (false-premise).** Questions whose premise is unsupported by the dialogue —
> asking about events, people, or facts that the user never mentioned. The correct response is
> a refusal or hedge. This category measures **hallucination resistance**, the load-bearing
> safety metric for any persona memory system (see Section 4.4).

**Confirmed: "adversarial" in this paper = false-premise QA only. 99.55% measures refusal /
hedge rate on 442 LoCoMo false-premise questions.**

### §4.4 rhetorical overreach

Quoted from §4.4 page 20:

> Adversarial robustness deserves its own discussion because it is structurally different from
> the other categories — and because **virtually no competing memory system reports it**.

Combined with Table 2's "Reports adversarial" column (Yes/No) and A-MEM's "(F1=50.0)" entry,
the paper treats "reports adversarial" as a binary capability claim across competitors — but
does NOT claim coverage of injection/poisoning/jailbreak in Synthius-Mem itself. The
"load-bearing safety metric" language in §4.4 further frames the SINGLE narrow metric as
comprehensive, which is the exact mislabel H-130 identifies.

## Five-axis defensible surface

A defensible adversarial metric surface would require:

| Axis | Benchmark | Synthius-Mem status |
|---|---|---|
| A1 False-premise QA (hallucination resistance) | LoCoMo adversarial subset | 99.55% ✓ |
| A2 Prompt injection (OWASP LLM01) | JailbreakBench, PromptBench, Lakera PINT | NOT MEASURED |
| A3 Memory poisoning / training-data poisoning | — (no published benchmark for memory systems) | NOT MEASURED |
| A4 Jailbreak / policy evasion | JailbreakBench, HarmBench | NOT MEASURED |
| A5 Temporal-adversarial (stale facts, retroactive edits) | — (future-work benchmark per §5.4) | NOT MEASURED |

**Only A1 is covered. The 99.55% claim generalizes to A1 only.**

## Erratum recommendation

The paper should either:
1. **Relabel** the metric as "False-premise refusal rate on LoCoMo adversarial subset:
   99.55%" throughout (abstract, §1, §7, keywords), retaining "adversarial robustness" as a
   sub-heading phrase within §4.4 where context narrows meaning; OR
2. **Report separately** on A2/A3/A4/A5 benchmarks (likely A2 injection via Prompt-Guard /
   Prompt-Shield eval; A4 jailbreak via JailbreakBench) and then retain the general
   "adversarial robustness" framing across the paper as a claim backed by 2-5 axis benchmarks
   combined.

Under current disclosure, the general framing is a rhetorical overreach relative to the
narrow empirical basis.
