## Primitive (a) — Per-stage exponential-backoff retry + DLQ (pseudocode)

```python
RETRYABLE_STATUS = {429, 500, 502, 503, 504}
NON_RETRYABLE_STATUS = {400, 401, 403, 404, 422}

def stage_retry(stage_name, fn, *args, max_attempts=3, base=1.0, cap=10.0, **kwargs):
    """
    stage_name ∈ {extract.biography, extract.experiences, ..., planner, answer, judge}
    Consolidation and storage stages are bound by T-032/T-033 and NOT wrapped here.
    """
    attempt = 0
    while attempt < max_attempts:
        try:
            return fn(*args, **kwargs)
        except (TimeoutError, ProviderError) as e:
            if e.status in NON_RETRYABLE_STATUS:
                dlq_send(stage_name, args, kwargs, reason=str(e))
                metrics.stage_dlq_count[stage_name] += 1
                raise
            if e.status in RETRYABLE_STATUS or isinstance(e, TimeoutError):
                delay = min(cap, base * (2 ** attempt) * random.uniform(0.5, 1.5))  # jitter
                time.sleep(delay)
                attempt += 1
                continue
            raise
    # terminal: DLQ
    dlq_send(stage_name, args, kwargs, reason="max_attempts_exceeded")
    metrics.stage_dlq_count[stage_name] += 1
    raise RetryExhausted(stage_name)

STAGES_WITH_RETRY = [
    "extract.biography", "extract.experiences", "extract.preferences",
    "extract.social_circle", "extract.work", "extract.psychometrics",
    "planner", "answer", "judge",
]
# 9 stages with retry/DLQ.
# Consolidation and storage: bound by T-032 (per-persona atomic txn) + T-033 (WAL);
# these commit-or-rollback atomically; no mid-operation DLQ meaningful.
```

## Primitive (b) — T-033 WAL replay (recovery procedure)

```python
def crash_recovery(persona_id):
    """
    Called on service startup OR on persona-circuit-breaker trip + manual heal.
    RPO ≤ 1s under fsync-each-commit; RTO ≤ 5min for 10 MB p75 persona.
    """
    snapshot = load_latest_snapshot(persona_id)  # materialized state
    wal_entries = fetch_wal_since(persona_id, snapshot.seq)

    state = snapshot
    seen_record_ids = set()
    for entry in wal_entries:
        # Idempotent record-ID dedup (entry.record_id is a deterministic hash over
        # (persona_id, op, domain, fact_id, before_hash, after_hash)).
        if entry.record_id in seen_record_ids:
            continue
        seen_record_ids.add(entry.record_id)
        state = apply_delta(state, entry)

    write_new_snapshot(persona_id, state, wal_entries[-1].seq)
    return state
```

**RPO arithmetic:** fsync-per-commit → single in-flight commit ≤ fsync latency (~1-10 ms on
local SSD; ~50-100 ms on networked EBS gp3). Upper bound RPO = 1 fsync ≈ **≤ 100 ms on EBS,
≤ 10 ms on local NVMe**. Paper-free 1s ceiling is well exceeded.

**RTO arithmetic:** T-030 p75 persona = 10 MB. WAL replay rate at ~100 MB/s throughput
(pessimistic) = **0.1 sec** raw IO. Plus snapshot write-back and application-init overhead
(~30 sec). **Total p75 RTO ≈ 30 sec**; p99 (99th percentile persona at 50 MB) ≈ 60 sec;
absolute ceiling at 500 MB hypothetical whole-tenant ≈ 5 min. Well within 5-min target.

## Primitive (c) — Persona-bounded blast radius (circuit breaker)

```python
class PersonaCircuitBreaker:
    def __init__(self, persona_id, error_threshold=0.05, window_sec=60):
        self.persona_id = persona_id
        self.error_window = TimeWindowCounter(window_sec)  # sliding 60s
        self.error_threshold = error_threshold
        self.state = "CLOSED"  # CLOSED / OPEN / HALF_OPEN

    def record(self, outcome):
        if outcome == "success":
            self.error_window.add_success()
        else:
            self.error_window.add_error()

        rate = self.error_window.error_rate()
        if self.state == "CLOSED" and rate > self.error_threshold:
            self.state = "OPEN"
            open_at = time.time()
            alert(f"persona {self.persona_id} circuit OPEN at rate={rate}")
        elif self.state == "OPEN" and (time.time() - open_at) > 120:
            self.state = "HALF_OPEN"

    def allow(self):
        return self.state in ("CLOSED", "HALF_OPEN")

# One breaker per active persona; breakers stored in a weak-ref map keyed by persona_id.
# Under T-018 persona-as-shard-key, tripping persona-A's breaker does NOT affect
# persona-B's shard (separate DB connection, separate WAL stream).
```
