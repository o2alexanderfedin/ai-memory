## Detection-LLM benchmarks (citations)

1. **Prompt-Guard-86M** (Meta, 2024): https://huggingface.co/meta-llama/Prompt-Guard-86M —
   reports 97.5% recall @ 1% FPR on injected-prompt detection; ~86M params, ~200ms CPU inference.
2. **Llama-Guard 3** (Meta, 2024): https://huggingface.co/meta-llama/Llama-Guard-3-8B —
   safety classifier; generalizes to injection detection patterns; cited in Anthropic and
   OpenAI safety documentation.
3. **PromptBench** (NeurIPS 2024, arXiv 2312.07910): published recall numbers for
   detector-LLM-based defenses in the 85-95% band.
4. **Lakera PINT** (Prompt Injection Test): standardized benchmark with 3000+ patterns; Gandalf
   public product uses detector-LLM as a layer.
5. **JailbreakBench** (NeurIPS 2024, arXiv 2404.01318): standardized benchmark for jailbreak
   robustness with published detector numbers.

## False-positive rate on benign text

Prompt-Guard-86M model card reports 0.5-1% FPR on benign user content. At 1% FPR on LoCoMo-class
chat (approx. 2K messages per persona × 200 personas = 400K messages per benchmark run), ~4000
false-flag messages — escalated to quarantine OR rerouted to a second LLM adjudication. Adds
cost but does not corrupt extraction quality. FPR remains well under the H-128b 10% ceiling.

## Integration recommendation

Two-stage pipeline:
```
User message
  ↓
[Detector LLM: Prompt-Guard-86M or gpt-4.1-nano with classification prompt]
  ↓ (injection_risk: float ∈ [0,1])
  ├─ if ≥ 0.95: quarantine + human review
  ├─ if ≥ 0.5: strip injection tokens + annotate provenance (H-139)
  └─ if < 0.5: pass through unchanged
  ↓
[6 domain extractors (H-128a guardrail sandwich as defense-in-depth)]
  ↓
Consolidation + storage
```

Defense-in-depth: H-128a (schema + sandwich + regex) runs AFTER the H-128b detector, not
instead of. `injection_risk` flows into T-009 provenance (via H-139 extension).
