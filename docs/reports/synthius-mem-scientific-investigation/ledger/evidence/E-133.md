### (c) Latency ≤50 ms per chat-length message

- Presidio-analyzer with `en_core_web_lg` + regex patterns on a 200-char chat message:
  **~5-20 ms on commodity CPU** (README benchmark, 2-core x86).
- spaCy `en_core_web_sm` alternative: **~2-5 ms** per message (lower recall, faster).
- Full pipeline (analyze → anonymize): **~10-30 ms** per message on typical chat.
- Bulk mode (batch 100 messages in parallel): amortizes to **~2-5 ms/msg**.

**≤50 ms ceiling is easily met.**

### (d) Tokenization + per-tenant vault is a documented pattern

Industry references:
- **Snowflake Dynamic Data Masking** + **External Tokenization** (docs.snowflake.com) —
  per-tenant masking policy, detokenize on role-authorized read. Native integration with
  Protegrity, ALTR, Baffle, Very Good Security (VGS).
- **Databricks Unity Catalog** — column-level masking with custom UDFs; tokenization via
  integration with Privacera, Immuta.
- **AWS Glue DataBrew** + **Amazon Macie** for discover-and-tokenize.
- **VGS (Very Good Security)** / **Skyflow** / **Evervault** — commercial per-tenant
  tokenization vaults with documented PCI-DSS scope reduction.
- **Microsoft Purview** — enterprise PII scanning with tokenization callouts.

**Pattern: deterministic encryption (AES-SIV or format-preserving) produces stable opaque
token per unique PII value; vault holds the reverse map keyed by per-tenant/per-persona
CMK (H-138). Reads with authorized scope detokenize; reads without scope see the opaque
token.**

### (e) Presidio or spaCy-NER achieves ≥90% recall on chat-like text

- **Presidio default** (`en_core_web_lg`): 0.88-0.94 F1 on CONLL-2003-like informal text
  (reported in PII-tagging benchmarks).
- **Stanza / GLiNER** alternatives: 0.92-0.96 F1 on chat-style text (GLiNER specifically
  tuned for zero-shot NER at chat length).
- **Anthropic/OpenAI LLM detectors (API-backed)**: 0.95+ recall but introduce
  PII-leaving-tenant concern (defeats the point of scrubbing).

**On LoCoMo-style chat:** the dominant PII types are PERSON (name — always present),
LOCATION (city, venue), DATE_TIME (event dates), and occasionally PHONE_NUMBER /
EMAIL_ADDRESS. All four map to well-measured Presidio types with ≥90% recall.

Chat-specific caveats:
- Informal names ("Bob", "Mel") may miss PERSON NER if not capitalized; recommend combining
  with Social-Circle alias table (T-015) for persona-specific recall boost.
- Typos and slang may lower recall ~3-5 pp; mitigated by regex fallback for numeric types
  (SSN, phone, credit card).

**Recall ≥90% on LoCoMo-class input is realistic with the default pipeline; stricter SLO
(≥95%) achievable by swapping to Stanza or GLiNER.**

## Integration pattern (recommended)

```python
from presidio_analyzer import AnalyzerEngine
from presidio_anonymizer import AnonymizerEngine
from presidio_anonymizer.entities import OperatorConfig

analyzer = AnalyzerEngine()
anonymizer = AnonymizerEngine()

def scrub_message(text: str, tenant_id: str, persona_id: str) -> ScrubResult:
    """
    Returns scrubbed text + redaction map for H-139 provenance.
    """
    results = analyzer.analyze(text=text, language="en",
                                entities=None)  # all built-in types
    # Tokenize: deterministic encrypt with per-tenant CMK (H-138)
    operators = {
        "PHONE_NUMBER": OperatorConfig("custom", {
            "lambda": lambda v: tokenize(v, tenant_id, "PHONE")
        }),
        "EMAIL_ADDRESS": OperatorConfig("custom", {
            "lambda": lambda v: tokenize(v, tenant_id, "EMAIL")
        }),
        "US_SSN": OperatorConfig("redact"),  # redact, never tokenize
        "CREDIT_CARD": OperatorConfig("redact"),
        # PERSON / LOCATION: tag with type
        "PERSON": OperatorConfig("replace", {"new_value": "[PERSON]"}),
    }
    scrubbed = anonymizer.anonymize(text=text, analyzer_results=results,
                                     operators=operators).text
    return ScrubResult(
        text=scrubbed,
        redactions=[{
            "type": r.entity_type,
            "original_token_hash": sha256(text[r.start:r.end], per_tenant_salt(tenant_id)),
            "replacement_tag": ...,
        } for r in results],
    )
```

Integrates with H-139 provenance extension (`pii_tokens_redacted`).
