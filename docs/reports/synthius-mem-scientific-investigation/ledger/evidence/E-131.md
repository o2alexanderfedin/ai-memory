## Method

## Four dimensions

### (i) OTel is the dominant tracing standard for multi-LLM services

- **OpenTelemetry Semantic Conventions for Generative AI**
  (https://opentelemetry.io/docs/specs/semconv/gen-ai/) — CNCF-standardized attributes:
  `gen_ai.system`, `gen_ai.request.model`, `gen_ai.response.model`,
  `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.operation.name`
  (chat/completion/embedding). Declared "Development" / "Experimental" but widely adopted
  across vendors by 2025-2026.
- **Langfuse** (OSS, 10K+ GitHub stars): OTel-compatible trace ingestion for LLM pipelines;
  production reference implementations documented.
- **LangSmith** (LangChain commercial): OTel-exporter and trace waterfall for multi-LLM
  chains.
- **Helicone** (OSS): OpenAI-compatible proxy emitting OTel traces with per-call span
  annotations.
- **Arize Phoenix** (OSS, 5K+ stars): OTel-GenAI instrumentation with fan-out span support
  (documents parallel tool-call traces).
- **Grafana Tempo + OTel Collector + Prometheus**: canonical OSS observability stack with
  documented LLM-fan-out integration.

**Production reference:** Both Langfuse and Arize Phoenix document GenAI fan-out span
patterns for parallel tool-call / parallel retrieval pipelines — matching Synthius-Mem's
6-extractor fan-out topology.

### (ii) 12 SLIs map cleanly onto SRE golden signals + LLM extensions

**SRE golden signals (Google SRE Workbook / Beyer et al. 2016):**
- Latency, Traffic, Errors, Saturation.

**Proposed H-131 12-SLI set mapped to golden signals + LLM-specific extensions:**

### (iii) Production LLM services report ≤15 SLIs at steady state

- **OpenAI status page**: ~6-8 top-level SLIs (API latency, error rate, queue depth, rate
  limit utilization) + per-model breakdowns.
- **Anthropic status page**: ~5-8 top-level SLIs.
- **Langfuse reference dashboard**: 9-12 canonical SLIs (cost/tok, p95 latency per model, error
  rate, groundedness, judge-win-rate).
- **Arize Phoenix**: 10-14 SLIs across (retrieval, generation, evaluation) phases.
- **Vellum / Humanloop / W&B**: 8-12 SLI default dashboards.

**12 SLIs is a reasonable MINIMUM for a multi-LLM pipeline with fan-out-6 extraction, planner,
answer, and judge stages. Typical production ceiling ~15-20 SLIs before alert fatigue.**

### (iv) Grafana + Prometheus + OTel supported for LLM fan-out

- **OTel Collector → Tempo** for traces, **→ Prometheus** for metrics, **→ Loki** for logs —
  three-pillars OSS pattern; Grafana visualizes all three.
- **Fan-out span support:** OTel supports parent-child span trees natively; a fan-out-6
  extraction produces 6 sibling spans under the extract-stage parent. Sampling is
  head-based at the root trace level (entire trace kept or dropped), avoiding per-span
  sampling distortion on the fan-out children.
- **Reference implementation:** Arize Phoenix documents exactly this pattern for LangChain
  parallel tool-calls; Langfuse ships a LangGraph integration for fan-out flows.
- **Prometheus exemplars** tie metrics to trace IDs — one SLI spike → click-through to the
  trace — standard workflow for the 12-SLI dashboard.

## Verdict

**PASS.** All four H-131 dimensions corroborated:
- (i) OTel is the dominant CNCF standard for GenAI tracing; ≥1 vendor production reference
  (Langfuse, Arize Phoenix, Helicone, LangSmith — multiple cited).
- (ii) Proposed 12 SLIs map cleanly onto 4 SRE golden signals + 3 LLM-specific extensions
  (quality, groundedness, judge).
- (iii) Production LLM services steady-state report 8-14 SLIs; 12 is a reasonable minimum,
  within ceiling.
- (iv) Grafana + Prometheus + OTel Collector + Tempo is a supported OSS stack; fan-out-6

Does NOT require ≥20 SLIs for SLO commitments. Stack is OSS, CNCF-standard, and
production-proven. Composes with H-131 SLI-12 for KMS audit trail (fed by H-138).
