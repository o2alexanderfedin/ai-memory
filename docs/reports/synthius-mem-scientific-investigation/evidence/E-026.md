### Storage DDL (PostgreSQL JSONB + functional indexes; NO FK constraints)

```sql
-- One physical file/table per domain; 6 total
CREATE TABLE biography_facts (
    persona_id   UUID NOT NULL,
    fact_id      UUID NOT NULL,
    category     TEXT NOT NULL,
    fields       JSONB NOT NULL,
    composite    TEXT,
    confidence   REAL NOT NULL CHECK (confidence BETWEEN 0 AND 1),
    provenance   JSONB,
    created_at   TIMESTAMPTZ NOT NULL,
    PRIMARY KEY (persona_id, fact_id)
);
CREATE INDEX idx_bio_category ON biography_facts (persona_id, category);
CREATE INDEX idx_bio_fields_gin ON biography_facts USING gin (fields jsonb_path_ops);
CREATE INDEX idx_bio_institution ON biography_facts ((fields->>'institution'));
CREATE INDEX idx_bio_year ON biography_facts (((fields->>'year')::int));

-- Category check enforced at application layer (no CHECK (category IN (...)))
-- No FK to social_circle.person_id — references are soft.
CREATE TABLE social_circle_persons (
    persona_id   UUID NOT NULL,
    person_id    UUID NOT NULL,
    names        JSONB NOT NULL,
    aliases      JSONB,
    closeness    REAL CHECK (closeness BETWEEN 0 AND 1),
    trust        REAL CHECK (trust BETWEEN 0 AND 1),
    PRIMARY KEY (persona_id, person_id)
);

CREATE TABLE experiences_facts (
    persona_id       UUID NOT NULL,
    event_id         UUID NOT NULL,
    summary          TEXT NOT NULL,
    parent_event_id  UUID,  -- intentional: NO FOREIGN KEY CONSTRAINT
    start_ts         TIMESTAMPTZ,
    end_ts           TIMESTAMPTZ,
    intensity        REAL,
    emotions         JSONB,
    social_context   JSONB,  -- [person_id] soft references
    PRIMARY KEY (persona_id, event_id)
);
-- ... preferences_facts, work_projects, psychometrics_facts analogously
```

Storage bullet "6 JSON files" is compatible: each domain is one logical JSONB-backed table or one JSON file per persona (500 MB / N personas ≈ 500-5000 KB per persona × 6 domains ≈ 83-833 KB per domain file — manageable). No cross-table FK constraints.

## Check (a): 21.79 ms Field-Level Matching on Typed Indices

Latency budget 21.79 ms on 500 MB / estimated ~200 K facts:
- Functional index `idx_bio_institution` on `fields->>'institution'` → O(log N) ≈ 20 comparisons for 200K rows → microseconds
- Bitmap index on `category` → prunes candidates to ~10% = 20K rows → further narrowed to ~100-1000 rows by category+institution
- Retrieve matching rows → <5 ms on SSD
- Serialize to prompt → negligible
- Total: ~1-5 ms for typical field-level lookup; 21.79 ms is comfortably met

This demonstrates field-level matching works on typed-field indices. ✓

## Check (b): "6 JSON Files" Not Contradicted

Two interpretations:
1. 6 literal JSON files per persona (one per domain) — possible at 500 MB scale with ~5000 personas (100 KB each × 6 files) = feasible
2. 6 logical tables in a JSONB store — also consistent with "JSON files" as descriptive rather than literal

DDL uses 6 tables (one per domain), each storing JSONB payload. No additional tables (no join tables, no constraint tables) → matches "6 JSON files" bullet. ✓
