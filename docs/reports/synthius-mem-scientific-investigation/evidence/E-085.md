### 2. Confidence function (evidence-count-based, NOT self-report)

```python
N_THRESHOLD = 5   # messages-supporting-trait threshold for "high" confidence

def confidence_from_evidence_count(evidence_count: int, N_threshold: int = N_THRESHOLD) -> float:
    """Non-LLM-self-report confidence. Avoids the known LLM-overconfidence failure mode."""
    return min(1.0, evidence_count / N_threshold)
```

Mapping to T-008 display bins (≥0.8 high / ≥0.5 medium / <0.5 low):
- 0 supporting quotes → confidence 0.0 → "low"
- 1 quote → 0.2 → "low"
- 2 quotes → 0.4 → "low"
- 3 quotes → 0.6 → "medium"
- 4 quotes → 0.8 → "high"
- 5+ quotes → 1.0 → "high"

### 3. Quotes selected by scoring LLM (H-081)

The H-081 scoring prompt instructs the LLM to emit up to 3 top-supporting quotes per trait as part of its structured output. The schema enforces `maxItems: 3`. The LLM selects by "strongest-support" heuristic — which quotes most clearly manifest the trait.

### 4. Token-footprint in answer system prompt

- 3 quotes × ~25 tokens/quote (short substring) × 5 traits per framework = ~375 tokens/framework
- At 9 frameworks, that's 3,375 tokens — FAR over the 300-token Psychometrics injection target.
- RESOLUTION: The answer system prompt (H-074/H-079) injects ONLY scores, not evidence quotes. Quotes are stored in the DB for audit/introspection, not injected into the answer LLM's context. ✓

Under H-079 compact form: 3 quotes × ~20 tok × top traits only (not all 45+ traits) = a bounded number. In practice, evidence quotes do NOT enter the answer prompt; they serve three other purposes:
- Audit trail (user can inspect "why does the system think I'm extraverted?")
- Cold-start regeneration (replay evidence through scoring)
- Confidence grounding (evidence count drives the confidence number)

### 5. Evidence-count-based confidence avoids LLM-overconfidence

Empirical fact: LLMs self-reporting confidence numbers tend to overconfidence (Lin et al. 2022 "Teaching Models to Express Their Uncertainty in Words"; Kadavath et al. 2022 "Language Models (Mostly) Know What They Know"). An LLM saying "I'm 90% confident" on a psychometric trait is poorly calibrated.

Evidence-count-based confidence sidesteps this: the LLM only emits quotes (a task it does reliably); the numeric confidence is computed deterministically from the quote count. No LLM self-assessment in the critical path. ✓

### 6. 3-quote cap handling of LoCoMo-scale fixtures

For a persona with 100+ messages clearly demonstrating extraversion, the LLM might find 20+ quotes supporting extraversion. The `maxItems: 3` cap preserves only the top 3 the LLM selects.

**Underdetermination concern:** If 3 quotes are insufficient to "underdetermine" a trait score, a user inspecting the audit trail sees only 3 quotes when dozens existed. Addressable by exposing a `total_supporting_quotes: integer` alongside the top-3 — the confidence function can use the full count while only storing 3 verbatim quotes. Let me extend the schema:

```json
{
  "trait": ...,
  "score": ...,
  "confidence": ...,
  "top_evidence": [...max 3...],
  "total_supporting_evidence_count": {"type":"integer"}
}
```

With this extension: confidence uses `total_supporting_evidence_count` (dense signal); UI shows `top_evidence` (bounded signal). ✓

## Reasoning

- Output schema drafted with bounded `top_evidence` (maxItems:3) and a clean separation of score, confidence, and supporting evidence.
- Confidence function is pure deterministic Python: `min(1.0, count/N_threshold)` avoids LLM self-report pitfalls.
- Mapping to T-008 bins (high ≥0.8 ↔ 5+ quotes; medium ≥0.5 ↔ 3+ quotes) is natural.
- The 3-quote cap is a storage bound (keeps the schema size finite), NOT a confidence cap — `total_supporting_evidence_count` field can carry the full count for calibration purposes.
- Quotes are stored in DB for audit/introspection but NOT injected into the answer system prompt (H-079 injects scores, not quotes) — this preserves the 1K answer-prompt budget.
- Non-LLM-self-report confidence is a material robustness improvement; quote count is a hard-to-fake signal.
