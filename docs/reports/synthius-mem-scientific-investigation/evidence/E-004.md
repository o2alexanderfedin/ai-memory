# E-004 Evidence — H-004 Biography 19-category enum derived from product-level taxonomy

OUTCOME: INCONCLUSIVE

## Pass/Fail criterion (verbatim)

> PASS iff WebSearch/WebFetch across (a) Wikipedia person-infobox field list, (b) US Census / SSA life-event taxonomy, (c) Synthius.ai blog posts, (d) any GitHub repo linked from Synthius.ai returns a ≥19-item life-domain list whose items overlap ≥80% with the proposed 19-member enum (education, employment, family, health, residence, nationality, religion, languages, relationships, finances, legal_status, military_service, hobbies, skills, achievements, beliefs, demographics, lifestyle, life_events). FAIL if no external source yields a comparable 19-item taxonomy, OR if Synthius.ai publishes a different list.

## Proposed 19-member enum under test

education, employment, family, health, residence, nationality, religion, languages, relationships, finances, legal_status, military_service, hobbies, skills, achievements, beliefs, demographics, lifestyle, life_events.

## Search strategy

Five WebSearch queries and four WebFetch calls, targeting each of the four evidence channels named in the criterion:

1. Wikipedia person-infobox field list — direct template fetch.
2. US Census and SSA life-event taxonomies — WebSearch for authoritative taxonomies.
3. Synthius.ai site content and sub-pages — direct fetch + enumeration of links.
4. GitHub repos linked from Synthius.ai; author GitHub profile (ArtemKislov).

## Evaluation vs. criterion

The criterion asks for any of four external sources to return a **≥19-item list with ≥80% overlap** with the proposed enum.

- **Wikipedia Person infobox**: publishes a field list, not a taxonomy of "life categories." Grouping its parameters yields ≈10–12 coherent life-domains (identity, birth, death, education, career, family, political office, criminal, awards, personal attributes). Even generously mapped, only ~8 of the 19 proposed categories align (education → alma_mater/education; employment → occupation/employer; family → spouse/children/parents; health → death_cause; residence → birth_place/resting_place; nationality → citizenship; achievements → awards/known_for; legal_status → criminal_charges). No clear mapping for: hobbies, skills, beliefs, lifestyle, life_events, finances, religion, languages, military_service, relationships, demographics. Overlap ≈ 8/19 = 42%. **Below 80% threshold.**

- **US Census / SSA**: SSA publishes 9 IRMAA events only; Census has demographic descriptors (race/ethnicity/household income) not a 19-item life-domain enum. Neither yields a ≥19-item list. **No match.**

- **Synthius.ai blog / About**: The public site (a) has no blog or docs section, (b) explicitly states the Dostoevsky example uses **12 biography categories, not 19**, and (c) does not enumerate the 12 by name. This is a **direct external contradiction of the "19" figure** appearing in the paper — but only at example-level; the paper's claim is the product-level schema covers 19 while the demo run may have populated only 12. The disclosed number on the live site is 12, and individual categories are undisclosed. **No match, but notable partial contradiction.**

- **Authors' GitHub**: ArtemKislov profile contains no Synthius repository; no code release; no taxonomy file. **No match.**

- **Holmes-Rahe SRRS (adjacent channel)**: 43-item list, but these are events (death of spouse, personal injury, major change in financial state), not life *domains*. Overlap with the proposed enum is on the order of 20–30% at best. Not the shape the criterion wants.

- **Luhmann et al. Big-Five life-events taxonomy**: 9 event-characteristic dimensions, not life-domains. No match.

None of the four criterion-named channels returned a ≥19-item life-domain list with ≥80% overlap.

## Verdict

OUTCOME: **INCONCLUSIVE** (not FAIL).

Rationale: the web-silence rule applies. Five search queries + ten URLs considered returned no authoritative 19-item life-domain enum that matches the paper's proposed list at ≥80% overlap. However, web-silence does not disprove the enum's existence inside Synthius.ai's private code, internal docs, or a future blog post. The most concrete external finding — that Synthius.ai's own public site quotes "**12 categories**" on its Dostoevsky demo — is a partial contradiction of the "19" figure but an insufficient disconfirmer (the 12 may be the subset *populated* by the Dostoevsky conversation corpus, while 19 remains the schema-level cardinality).

Noteworthy secondary finding: the authoritative life-event taxonomies we did find (SRRS 43, SSA 9, Census demographics, Big Five 9-dimension) are **structurally incompatible** with a closed 19-item life-*domain* enum. If Synthius-Mem's 19 categories came from such a source, it would have to be a heavy editorial reshaping — which makes the more likely origin either (i) a Synthius-internal product taxonomy (not external) or (ii) a Wikipedia-infobox-style grouping editorially expanded. Both are consistent with H-004's "product-level taxonomy" claim but neither is externally verifiable.

This INCONCLUSIVE result strengthens the case for **H-005** (empirically-derived, not inherited from a named framework) and weakens the verifiability of **H-004**'s specific 19-member list. A definitive test requires the paper's appendix or a future Synthius code release.
