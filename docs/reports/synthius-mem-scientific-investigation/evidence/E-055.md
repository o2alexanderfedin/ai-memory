## Arithmetic prong: 740 tok/msg × 6 domains consistency with GPT-4.1-mini

App. A.1 says extraction amortizes to 740 tok/msg across N=500 messages (i.e., ~370K total extraction tokens). The hypothesis expects 740 × 6 ≈ 4,440–5,040 tok/msg for 6 separate per-domain calls.

But wait — Table 7 says total is "~5,040" and itemizes: "~2,000 tok retrieved + 1,100 tok planner + 740 tok extraction + 1,000 system + 200 output = 5,040". The 740 is NOT the per-call extraction — it is the per-message amortized extraction cost. This is a single number with no per-domain breakdown. It does not confirm 6 concurrent calls (that's E-062's job) and is silent on which model runs them.

App. A.3 USD pricing (Line 126):
> "All conversions use **GPT-5.4 pricing** as of April 2026: $2.50/M input tokens, $15/M output tokens."

**Critical finding**: App. A.3 uses **GPT-5.4**, not GPT-4.1-mini, for USD pricing. GPT-4.1-mini public pricing as of April 2026 would be ~$0.40/M input. If the extraction model were GPT-4.1-mini, using GPT-5.4 pricing overstates cost by ~6×. If the model WERE GPT-5.4, extraction cost would be dominated by the answer LLM cost and the "5× cheaper than full context" headline might compress.

The USD figures in Table 8 ($0.011/msg for Synthius-Mem) imply 5,040 tokens × $2.50/M = $0.0126 input-side — close to $0.011. The arithmetic checks out for GPT-5.4 pricing. But §4.4 says Synthius-Mem's answer generation uses GPT-4.1-mini, not GPT-5.4 — so App. A.3's GPT-5.4 pricing is a **projection** for a different (newer) model, not Synthius-Mem's actual production model. The paper is self-inconsistent here.

## Final verdict

- Plausible as a same-family consistency argument (answer + judge are GPT-4.1-mini per line 82).
- Not explicitly supported by any paper passage.

- Weakened by App. A.3's use of GPT-5.4 pricing in place of GPT-4.1-mini pricing — a latent internal inconsistency.

## Notable findings

1. **Methodological inconsistency across models**: Synthius-Mem uses GPT-4.1-mini for answer+judge, but baselines use Gemini 3 Flash as answer LLM. Cross-vendor tokenizer differences (~1.3 tok/word each but not identical) undermine strict apples-to-apples token accounting in the "~5× more efficient" headline (§4.5).

2. **GPT-5.4 pricing in App. A.3**: The USD conversion uses GPT-5.4 (April 2026 pricing $2.50/$15 per M tokens), a *newer* model than the GPT-4.1-mini used for answer+judge per §4.4. This is either (a) a projection to a future-deployed model, or (b) a latent inconsistency between the evaluation (GPT-4.1-mini) and the cost model (GPT-5.4). Either way, the USD figures in Tables 8 and the "per-message cost" comparisons are NOT derived from the same model that produced the 94.37% accuracy number.

3. **Answer model vs. extraction model asymmetry**: The paper explicitly names the answer model (GPT-4.1-mini, line 82) and the judge model (GPT-4.1-mini, line 82) but never the extraction model. For a system whose key claim is structured persona extraction, silence on the extraction model is a significant reproducibility gap — future wave should elevate this as a G-??? (Gap). This observation aligns with E-055/E-056 competing hypotheses: either extraction uses GPT-4.1-mini (consistency of family, H-055) or it uses a heavier local model (H-056) — the paper supports neither explicitly.
