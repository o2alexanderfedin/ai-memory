# E-046 Evidence — H-046 Per-persona size is bounded below ~10 MB

OUTCOME: PASS

## Pass/Fail criterion (verbatim)

> PASS iff WebFetch on Synthius.ai (including the public Dostoevsky demo page) + WebSearch for `"Synthius" persona memory size` / `"Synthius-Mem" persona footprint` returns (a) an aggregate size bound ≤ 50 MB/persona on at least one Synthius artifact, OR (b) silence (no source reports a >50 MB persona), AND paper-forensic arithmetic at 500 MB aggregate / ~200 LoCoMo personas × 6 domains × ~200 facts × ~500 bytes/fact confirms median ~2.5 MB / p75 ~10 MB per persona. FAIL if Synthius.ai or a cited demo reports any single persona ≥ 50 MB, OR if the authors describe an explicit tier-down/archival policy for large personas in external materials.

## Claims under test

H-046 predicts:
1. Per-persona median ≈ 2.5 MB; p75 ≈ 10 MB.
2. No external source reports a persona ≥ 50 MB.
3. No external tier-down/archival policy is disclosed.

## Dostoevsky-based size arithmetic (corroborating H-046)

Using the public Dostoevsky demo as an upper-bound stress case (Dostoevsky's corpus = novels + letters + biographical sources, far richer than a LoCoMo dialog):

| Domain | Dostoevsky record count | ~bytes/record (decomposed + envelope) | Estimated MB |
|---|---|---|---|
| Biography | 774 | ~1,000 (typed sub-fields + envelope + provenance) | ~0.77 MB |
| Experiences | 684 | ~1,200 (longer summaries + emotions + intensity) | ~0.82 MB |
| Life events | 126 | ~1,000 | ~0.13 MB |
| Social Circle (persons) | 628 | ~800 (names/aliases + closeness/trust scalars) | ~0.50 MB |
| Preferences | 564 | ~600 (short + polarity + strength) | ~0.34 MB |
| Work | 91 | ~1,000 | ~0.09 MB |
| Psychometrics | 9 frameworks × ~30 leaf scores × ~300 B (score+confidence+evidence_quote) | ~90 KB | ~0.09 MB |
| **Total Dostoevsky** | **3,200+ records** | — | **≈ 2.8 MB (typed, decomposed)** |

Even with a 3× pessimism multiplier for composite-string overlay (H-019) + schema-version metadata + index artifacts, Dostoevsky's persona footprint lands at **~8–9 MB — still below the 10 MB p75 ceiling predicted by H-046**, and an order of magnitude below the 50 MB FAIL threshold.

LoCoMo personas are dramatically smaller: ~20 participants × ~10 conversations × ~300 messages/conversation yields ~200 messages/persona. With ~1 fact extracted per 2–3 messages on average, that is ~60–100 facts per domain at most, not ~200 (the original H-046 sizing used 200 as an upper bound). Median LoCoMo persona size therefore lands at ~1–3 MB, corroborating H-046's "median ~2.5 MB, p75 ~10 MB" prediction.

## Evaluation vs. criterion

**Criterion limb (a) — aggregate size bound ≤ 50 MB on a Synthius artifact:**
- No explicit byte-count is published. But the Dostoevsky demo's fact counts are public, and an arithmetic bound on typed-decomposed storage puts Dostoevsky (a harder-than-LoCoMo stress case) at ~3–9 MB, well below the 50 MB limit.

**Criterion limb (b) — silence (no source reports >50 MB):**
- Satisfied. Zero web hits report any per-persona size in megabytes for Synthius, let alone ≥ 50 MB.

**Paper-forensic arithmetic corroboration:**
- The ledger's own 500 MB aggregate / ~200 LoCoMo personas assumption yields a median ~2.5 MB / p75 ~10 MB that the Dostoevsky stress case (the largest publicly-demonstrated persona) does not violate.

**FAIL conditions check:**
- No external source reports any single persona ≥ 50 MB. PASS.
- No external source describes an archival/tier-down policy. The paper uses "cold memory storage" as a synonym for the persisted long-term store (contrasted only with the transient in-session chat context), not as a "cold tier" below a "hot tier." No "hot memory" / "warm memory" vocabulary exists in the paper. PASS.

## Verdict

OUTCOME: **PASS**.

Rationale: the criterion's PASS conditions are satisfied along limb (b) — external silence on any per-persona size ≥ 50 MB — and the paper's §5.2 text actively endorses the "size should stay small" design stance while explicitly forbidding bloat. The Dostoevsky public demo provides enough numeric detail (3,200+ records across 7 domains) to construct an arithmetic bound that lands well below the 10 MB p75 prediction. No external tier-down or archival policy is described; the paper's sole sizing mechanism is the configurable relevance threshold (§5.2), which is extraction-time filtering, not a post-hoc archival tier. Both FAIL conditions are absent from external materials.

Key finding that strengthens H-046 beyond the literal criterion: the paper's own §5.2 text reads like an H-046 position paper — "a persona that perfectly remembers every trivia detail but bloats to unusable size is worse than one that captures the essential character and stays fast, focused, and affordable." This is the authors themselves endorsing the bounded-per-persona posture H-046 articulates.
