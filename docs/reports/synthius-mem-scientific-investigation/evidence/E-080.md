### 1. Aggregator pseudocode

```python
import tiktoken
ENC = tiktoken.get_encoding("cl100k_base")

def pack_domain_facts(facts: List[FactItem], token_budget: int) -> List[FactItem]:
    """Stable sort (recency DESC, confidence DESC, fact_id ASC) → pack atomically."""
    sorted_facts = sorted(facts,
        key=lambda f: (-iso8601_epoch(f.updated_at), -f.confidence, f.fact_id))
    out, used = [], 0
    for f in sorted_facts:
        block = render_fact_as_json(f)
        t = len(ENC.encode(block))
        if used + t > token_budget:
            break   # atomic — no mid-item truncation
        out.append(f)
        used += t
    return out

def aggregate_context(per_domain_facts: Dict[str, List[FactItem]],
                      planner_domain_order: List[str],
                      total_budget: int = 2000) -> str:
    k = len(planner_domain_order)
    per_domain_budget = total_budget // k
    header_tokens = 5   # "## Domain\n" budget
    body_budget = per_domain_budget - header_tokens

    sections = []
    for domain in planner_domain_order:
        facts = per_domain_facts.get(domain, [])
        packed = pack_domain_facts(facts, body_budget)
        sections.append(format_domain_section(domain, packed))
    return "\n".join(sections)
```

### 2. Atomic-no-mid-item truncation

The `break` in `pack_domain_facts` ensures a fact is either fully included or fully excluded — no partial JSON. ✓

### 3. Planner-declared order preservation

**Fixture B — 3 domains (Biography + Work + Preferences), 10 facts each:**

- Biography (55 tok/fact × ≤12 facts within 666 tok) → 10 facts × 55 = 555 < 666 → all 10 fit.
- Work (65 tok/fact × ≤10 facts) → 10 facts × 65 = 650 < 666 → all 10 fit.
- Preferences (~38 tok/fact) → 10 × 38 = 380 < 666 → all 10 fit.
- **Total: ~1,595 tokens.** Within 2K. ✓

**Fixture C — 4 domains (Biography + Work + Preferences + Social Circle), 12 facts each:**
- Per-domain budget = 2000/4 = 500 tok (less 5 for header = 495).
- Biography (55 tok): floor(495/55) = 9 facts (9×55 = 495; last fact fits exactly).
- Work (65 tok): floor(495/65) = 7 facts (7×65 = 455; 8th would be 520 > 495 → atomic break at 7).
- Preferences (38 tok): floor(495/38) = 13 → but only 12 available → 12 × 38 = 456 tokens.
- Social Circle (70 tok): floor(495/70) = 7 facts (7×70=490).
- **Total: 9×55 + 7×65 + 12×38 + 7×70 + 4×5 (headers) = 495+455+456+490+20 = 1,916 tokens.** Within 2K. ✓

All three fixtures land in [1,595, 1,916] tokens — broadly matching the "1,800-2,000" target band (fixture B undershoots because each domain has lightweight fact shapes; Fixture C is at the upper end and approaches the cap).
