# E-094 Evidence

**OUTCOME: PASS**

**Experiment:** E-094 (artifact-construction) — Hypothesis H-094 (§4.6 "<0.1% of total latency" claim is rhetorical overreach by ~1 order of magnitude)
**Pass criterion:** Realistic GPT-4.1-mini p50 TTL ≈ 1.2-1.5s; 21.79 ms / ~1500 ms ≈ 1.45% (not <0.1%).

## Arithmetic

Paper §4.6 verbatim: "CategoryRAG operates at 21.79 ms mean latency … the memory retrieval component contributes less than 0.1% of total latency."

For the "<0.1%" claim to hold: retrieval_ms / total_ms < 0.001 ⇒ total_ms > 21.79 / 0.001 = **21,790 ms = 21.79 s**.

### Realistic GPT-4.1-mini end-to-end latency

Public benchmarks for GPT-4.1-mini (OpenAI GPT-4.1-mini, released April 2025; pricing $0.15/M in, $0.60/M out) for ~200 output tokens on ~5K input tokens:

- OpenAI platform docs + ArtificialAnalysis.ai typical measurements: p50 ≈ **1.0-1.5 s**, p95 ≈ 2.5-3 s.
- Azure OpenAI p50 ≈ 1.2-1.8 s (slightly slower than OpenAI direct).
- Fireworks/Together-style hosted GPT-4.1-mini-equivalents: similar range.

Use p50 = 1,500 ms (midpoint) as the canonical "typical" end-to-end.

### Retrieval share at realistic latency

| Total end-to-end | Retrieval share |
|---|---|
| p50 ≈ 1,000 ms | 21.79 / 1000 = **2.18%** |
| p50 ≈ 1,500 ms | 21.79 / 1500 = **1.45%** |
| p95 ≈ 3,000 ms | 21.79 / 3000 = **0.73%** |
| p99 ≈ 5,000 ms | 21.79 / 5000 = **0.44%** |
| For <0.1% to hold: | total ≥ 21,790 ms (21.79 s) |

At p50 the retrieval share is **1.45%** — 14.5× larger than the paper's "<0.1%" claim. For the paper's claim to be true, total end-to-end would need to exceed ~22 seconds, which is 10-15× typical and would imply the system is dominated by latency the authors explicitly frame as non-bottleneck.

### Sensitivity: what if retrieval is actually ~1 ms?

If the "21.79 ms" figure were itself a display error (really ~1-2 ms) then:
- 2 ms / 1500 ms = 0.133% — still > 0.1%
- 1 ms / 1500 ms = 0.067% — < 0.1% barely

But paper's Figure 9 plots 21.79 ms explicitly and contextualizes against Pinecone/Weaviate at "15-20 ms" — the 21.79 ms is treated as Real and is the anchor number for the "3000× faster than LangMem" claim. The figure is not misreported.

### Order-of-magnitude verdict

The "<0.1%" claim is off by approximately **1 order of magnitude** in the retrieval-share direction (0.1% vs realistic 1.45% = 14.5× gap). This is a **load-bearing rhetorical overreach**, not a measurement error — but the correction is minor because either 1.45% or 0.1% yields the same architectural conclusion ("retrieval is negligible relative to LLM inference").
