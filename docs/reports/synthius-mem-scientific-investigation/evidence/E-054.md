## Arithmetic prong: App. A.1 consistency with cl100k_base

App. A.1 Table 7 (Line 126) numbers: 1K system prompt, 2K retrieved context, 1.1K planner, 200 output, 740 tok/msg amortized extraction, 25K full-context replay at N=500.

Reference conversion factor for cl100k_base on English prose: ~1.3 tokens/word (OpenAI published ratios for mixed English prose). So:
- 1,000 tokens ≈ 770 English words (~3,500–4,000 characters). A 1K-token system prompt is roughly a 1.5-page text — plausibly sized for a persona-injection + refusal-policy + role-section scaffolding.
- 25,000 tokens ≈ ~19,000 words. At 500 messages × 50 tokens/message = 25K. This gives ~38 words/message — realistic for casual chat. Consistent with cl100k_base.
- 2,000 retrieved tokens → ~1,500 words → a compact multi-domain JSON bundle is plausible.
- 740 tok/msg amortized extraction: dividing the end-to-end extraction cost by N=500 messages implies ~370K tokens of extraction across the conversation. For 6 domains × ~500 messages × ~120 tokens/message chunk ≈ ~360K — in the same order of magnitude. Consistent.

None of these numbers reveal the tokenizer identity. They are compatible with cl100k_base AND compatible with Gemini SentencePiece (similar token/word ratios in the ~1.3 range) AND with LLaMA BPE (~1.3 range). The arithmetic does not discriminate.

## Final verdict

INCONCLUSIVE. The paper's silence on tokenizer identity is the primary signal. H-054 claim (cl100k_base) is consistent with (i) the confirmed OpenAI-family answer + judge model (GPT-4.1-mini), (ii) the App. A.1 numbers not contradicting cl100k_base, and (iii) zero hits naming any competing tokenizer. However, "zero hits" is weak evidence because a pass-by-silence finding cannot distinguish cl100k_base from unnamed alternatives. The criterion requires EITHER silence OR explicit reference — silence is present but not load-bearing.

Downgrading from PASS to INCONCLUSIVE because:
1. The criterion's (a) disjunct (silence) is satisfied, but (b) arithmetic prong does not tightly discriminate cl100k_base from LLaMA BPE or Gemini SentencePiece (all ~1.3 tokens/word).
2. The extraction-model identity (H-055) is itself unsettled — the paper never names the extraction model explicitly — so the inferred-from-GPT-4.1-mini chain of reasoning has a weak link at extraction.
3. Sibling E-055 (below) needs to resolve whether the extraction LLM is OpenAI-family before H-054 can be strengthened to PASS.

## Surprising finding

The paper uses **Gemini 3 Flash** as the baseline answer LLM (line 63), while using **GPT-4.1-mini** as Synthius-Mem's answer + judge (lines 59, 82). This is a **methodologically inconsistent** comparison setup: different model families for the system-under-test vs. the baseline. The Gemini 3 Flash model has its own SentencePiece-family tokenizer, so the "tokens per message" numbers in App. A.1 Table 7 are not strictly comparable across Synthius-Mem (GPT-4.1-mini / cl100k_base) and baselines (Gemini 3 Flash / SentencePiece) without a tokenizer-conversion factor — an issue the paper does not address. This cross-tokenizer comparison concern is distinct from H-054 but deserves to be flagged as G-???-new for a future wave. The 5× token-efficiency claim (§4.5) is weakened to the extent that token counts are not apples-to-apples across tokenizers.
