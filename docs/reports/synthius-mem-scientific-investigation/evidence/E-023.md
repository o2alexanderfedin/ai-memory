## Evaluation vs. criterion

**Prong 1 — two independent external sources advocating ULID for memory/time-sortable records:**

Far more than two independent sources support ULID over UUIDv4 for memory-store and event-sourcing-adjacent use cases. Highlights:

1. **Honeybadger blog** — explicit "use ULID for database keys" recommendation.
2. **Medium / akemara** — "Goodbye Random Inserts" comparative analysis, ULID/UUIDv7 over UUIDv4.
3. **incident.io production blog (lawrencejones.dev)** — real-world ULID adoption in an event-driven platform, rollback and audit use cases.
4. **ByteAether 2025 technical guide** — recommends ULID/UUIDv7 as modern default.
5. **Inferable.ai** — ULID for AI-infrastructure log readability.
6. **arxiv 2509.08969** — peer-review-track benchmark showing ULID outperforms UUIDv4 on generation speed and network overhead.
7. **Barkey Wolf event-store post** — explicit use of ULID for **event-store time-sorted ordering**, which is the exact pattern a reversible-diff-engine with rollback needs.

Seven independent sources far exceed the "at least two" threshold. **Prong 1 satisfied.**

**Prong 1b — ULID compatibility with reversible-diff-engine rollback semantics:**

The Barkey Wolf event-store post is the load-bearing source here: it shows ULID-keyed event stores support append-only ordering with lexicographic retrieval, which is precisely the property a reversible diff engine needs for (a) correct replay order, (b) monotonic diff-log append, (c) range-scan for rollback to a named point. The canonical ULID spec's monotonicity guarantee (within-ms ordering) maps directly onto "full rollback capability" language in Synthius-Mem §3.3.

In contrast, UUIDv4's randomness actively *breaks* replay ordering: a diff log keyed by UUIDv4 cannot be sorted by insertion order without a separate timestamp column, which creates ordering-column/ID-column consistency risks at crash-recovery time. **Prong 1b satisfied.**

**Prong 2 — no paper artifact contradicts non-random ID choice:**

- arxiv abstract: silent. GAPS.md G-010 confirms silence throughout the paper on ID format.
- synthius.ai: silent on ID format.
- No paper text names "UUID" or "random ID" or "UUIDv4." There is no positive assertion of pure random IDs anywhere.

**Prong 2 satisfied.**
