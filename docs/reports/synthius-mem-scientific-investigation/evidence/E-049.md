## Drafted WAL record schema

```json
{
  "record_id":       "<monotonic seq, persona-scoped>",
  "persona_id":      "<uuid>",
  "seq":             42,
  "op":              "add",                  // enum: add | edit | delete
  "domain":          "biography",            // one of 6 domains
  "fact_id":         "<fact uuid>",
  "delta": {                                 // structured diff payload
    "before": null,                          // null on add
    "after":  { "fields": {...}, "envelope": {...} },
    "fields_changed": ["institution","year"] // subset for edit/delete paths
  },
  "timestamp":       "2026-04-21T19:05:00Z",
  "extractor_version": "syn-ext-0.12.3"
}
```

Storage: per-persona append-only file (Postgres: `wal(persona_id, seq bigserial, record jsonb)` indexed on `(persona_id, seq)`; SQLite: a per-persona `wal` table with INSERT-only semantics).

Invariants:
- `seq` is monotonic per persona. Strictly increasing.
- `record_id` is content-addressable (`hash(persona_id, seq, op, domain, fact_id, delta)`) — enables idempotent replay deduplication.
- `extractor_version` carries provenance for T-009; required for rollback semantics (only replay up to a given extractor version).

## Drafted replay algorithm

```python
def replay_from_snapshot(persona_id: str, snapshot_seq: int | None):
    """Rebuild the 6 domain JSONs by replaying WAL from snapshot_seq onward."""
    state = load_snapshot(persona_id, at_seq=snapshot_seq) if snapshot_seq else empty_state()
    wal_records = iter_wal(persona_id, after_seq=snapshot_seq or 0)

    seen_record_ids = set()
    for rec in wal_records:
        if rec.record_id in seen_record_ids:
            continue                            # idempotent dedup on crash-retry
        seen_record_ids.add(rec.record_id)

        if rec.op == "add":
            state[rec.domain][rec.fact_id] = rec.delta.after
        elif rec.op == "edit":
            existing = state[rec.domain].get(rec.fact_id, {})
            state[rec.domain][rec.fact_id] = deep_merge(existing, rec.delta.after)
        elif rec.op == "delete":
            state[rec.domain].pop(rec.fact_id, None)

    return state

def materialize_snapshot(persona_id: str):
    """Atomically write the rebuilt state as a new snapshot (Postgres txn or SQLite file rename)."""
    state = replay_from_snapshot(persona_id, snapshot_seq=latest_snapshot_seq(persona_id))
    with atomic_write(persona_id) as handle:
        handle.write(serialize(state))
    record_new_snapshot(persona_id, seq=current_wal_seq(persona_id))
```

Idempotence properties:
- **Operation idempotence**: `add` + `add` of same `fact_id` = `add` (the second overwrites; state converges).
- **Record-id dedup**: re-processing the same WAL record (e.g., after crash) is a no-op via `seen_record_ids`.
- **Delete replay**: deleting an already-deleted fact is a no-op (`pop` with default).
- **Merge semantics**: `deep_merge` on `edit` is associative and commutative on disjoint field sets.

## Crash-recovery flow

```
Initial state:
  [snapshot @ seq=100]                ← durable on disk
  [WAL records 101..137]               ← durable on disk
  [in-flight consolidation batch]      ← not yet WAL-appended; lost on crash

After crash at t=<between seq=137 and seq=138>:
  1. Open WAL, scan to find max(seq) = 137.
  2. Load snapshot @ seq=100.
  3. Replay WAL[101..137] via replay_from_snapshot().
  4. Resulting state matches pre-crash durable state.
  5. In-flight consolidation batch is lost — safe: not yet visible to any reader.

  Retrieval at 21.79 ms: query hits the MATERIALIZED state (snapshot +
  replayed overlay), NOT the WAL log directly. Log-free read path.
```

## §3.3 reversible diff rollback

Paper: "reversible diff engine that supports add, edit, and delete operations with full rollback capability."

H-049 implements this natively:
```python
def rollback_to_seq(persona_id: str, target_seq: int):
    """Rebuild state as of seq=target_seq; discard WAL records seq > target_seq."""
    state = replay_from_snapshot(persona_id, snapshot_seq=None)  # from start
    # Stop replay at target_seq — everything above is "undone."
    wal_records = [r for r in iter_wal(persona_id) if r.seq <= target_seq]
    for rec in wal_records:
        apply(state, rec)
    materialize_snapshot_with_seq(persona_id, target_seq)
    truncate_wal_above(persona_id, target_seq)
```

Rollback = replay from origin up to a chosen seq. Because WAL records carry the `delta.before/after` pair, each individual op is reversible (swap before/after) if the product chooses point-wise undo instead of full rollback. Both semantics are supported by the same WAL schema.

def gdpr_erase(persona_id: str):
    """Right to erasure: remove all trace of persona from WAL, snapshots, indexes."""
    # Step 1: delete all WAL records for this persona (tombstone).
    execute("DELETE FROM wal WHERE persona_id = $1", persona_id)
    # Step 2: delete all domain rows for this persona (cross-domain transactional).

Log compaction is trivially supported: because WAL is per-persona-scoped (`WHERE persona_id = $1`), erasure is a single delete over the WAL table. No cross-persona crawl needed. Snapshot materialization after erasure is a no-op (the persona's state set is empty).
