### Reconciliation with paper's claim

Paper §4.6 says "LangMem (~60 s)" — this matches LangMem's **p95 latency on LoCoMo** as measured by Mem0's published benchmark (59.82 s ≈ 60 s). The 60 s figure is **not a typo**; it is the rounded p95 from a real published benchmark.

### What H-095 got wrong

H-095's predictions:
- "No cited source supports 60 s" — **false**; Mem0 paper (Singh et al., 2025, arXiv:2504.19413, which IS cited in Synthius-Mem's reference list) reports LangMem p95 ≈ 59.82 s on LoCoMo.
- "60 s is 10³× the nearest measurement" — partially true (Mem0 = 200 ms, so 60 s = 300× Mem0), but this is because LangMem is genuinely a slow synchronous-retrieval implementation, not because the number is a typo.
- "Mem0-Graph 480 ms is the next-slowest" — 60 s is indeed an outlier, but it is a REAL outlier, not a false one.

### Remaining methodological concern (H-095 residual)

The paper cites "LangMem (~60 s)" in §4.6 but does not cite the **source** of that 60 s figure. A reader reviewing §4.6 sees the number without knowing it comes from Mem0's benchmark on LoCoMo. This is a minor citation-hygiene gap, not a typo.

Additionally, the comparison "21.79 ms / 60 s = 2,755× faster" is technically correct but somewhat unfair: LangMem's 60 s p95 is the WORST-configuration measurement (p50 is 17.99 s, still bad); Synthius-Mem's 21.79 ms is a mean (not p95). A like-for-like comparison (both p95) would narrow the gap to ~21.79 ms p95 vs 59.82 s p95 = **2,744×**, essentially the same headline.

## Verdict

**FAIL for H-095** (the "unsourced typo" claim). The 60 s figure is a real LangMem p95 retrieval latency on LoCoMo as published in Mem0's benchmark (which is one of the paper's own cited references — Singh et al. 2025, arXiv:2504.19413). H-095 is refuted.
