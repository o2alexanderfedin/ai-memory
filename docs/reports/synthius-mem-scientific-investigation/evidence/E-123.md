## Per-component golden-set suite specification

### Suite A — Extraction golden set (100 × 6 = 600 fixtures)

**Purpose:** Verify each domain's extraction pipeline emits the expected FactItem structure for canonical inputs.

**Fixtures:**
- 100 canonical messages × 6 domains = 600 (input, expected_output) pairs.
- Input: a single LoCoMo-style conversation chunk (1-20 messages).
- Expected output: a FactItem list conforming to the domain schema.

**Example (Biography):**
```yaml
input: |
  User: I got my PhD in Neuroscience from UCL in 2019.
expected:
  - persona_id: "test_001"
    domain: "biography"
    payload:
      category: "education"
      degree: "PhD"
      field: "Neuroscience"
      institution: "UCL"
      year: 2019
      precision: "year"
    confidence: {gte: 0.8}
    provenance: {has_source_message_id: true}
```

**Regression gate:** Extraction F1 (fact-level precision + recall against gold FactItem set) per domain; any per-domain F1 drop > 1 pp = CI fail.

### Suite B — Planner routing golden set (100 fixtures)

**Purpose:** Verify planner routes LoCoMo-style questions to the correct domain(s) via tool calls.

**Fixtures:**
- 100 LoCoMo-style questions × expected tool-call routing.
- Single-domain fixtures (80): "What is Alice's degree?" → `call(biography_retriever, query="degree")`
- Multi-domain fixtures (20): "What does Alice think about her job?" → `call(work_retriever), call(psychometrics_retriever)`

**Example:**
```yaml
question: "Where does Bob work?"
expected_tool_calls:
  - tool: "work_retriever"
    params: {persona_id: "bob", query: "employer"}
```

**Regression gate:** 
- Routing accuracy = % fixtures where all expected tool calls are emitted (no missing, no extra).
- Threshold: ≥ 95%; drop > 2 pp = CI fail.

### Suite C — Consolidator dedup/merge golden set (50 fixtures)

**Purpose:** Verify 3-stage hybrid consolidation (per T-046): Stage 1 rule-based SHA-256 dedup; Stage 2 rule-based merge; Stage 3 LLM adjudication for ambiguous.

**Fixtures:**
- 50 conflict-pair fixtures: (old_fact, new_fact) pairs with expected resolution.
- SHA-256 exact duplicates (15): both facts produce same hash → Stage 1 dedup, keep one.
- Deterministic merge (20): facts overlap but differ in one field → Stage 2 merge (e.g., update "year: 2018" → "year: 2019" with provenance-aware accept-newer).
- LLM-escalation (15): semantically similar but uncertain → Stage 3 LLM adjudicates (e.g., "Alice works at Google" vs "Alice joined DeepMind" — may be promotion/move, or conflict).

**Example:**
```yaml
old_fact: {category: "education", degree: "PhD", field: "Neuroscience", institution: "UCL", year: 2018}
new_fact: {category: "education", degree: "PhD", field: "Neuroscience", institution: "UCL", year: 2019}
expected:
  resolution: "stage2_deterministic_merge"
  merged: {...old_fact..., year: 2019}  # accept newer year with provenance
```

**Regression gate:**
- Stage 1 precision: 100% (exact dedup is a pure hash-equality check).
- Stage 2 precision: ≥ 98%; drop > 0.5 pp = CI fail.
- Stage 3 escalation rate: 10-30% expected; >40% indicates the rule-based stages are missing cases.

### Suite D — Judge rubric golden set (100 fixtures)

**Purpose:** Verify judge's binary rubric is strict and consistent with a human-assigned baseline.

**Fixtures:**
- 100 Q-A pairs × human-assigned 1/0 labels (2+ annotators + majority vote).
- Stratified by category: Adversarial (20), Core (30), Temporal (20), Open inference (15), Peripheral (15).
- Per H-112: 2+ human annotators + Cohen's κ reported as secondary metric.

**Example:**
```yaml
question: "When did Alice get her PhD?"
gold: "2019"
candidate_1: "Alice got her PhD in 2014."  # wrong year
candidate_2: "I believe Alice completed her doctoral program in 2019." # correct
expected_judge_1: 0  # wrong
expected_judge_2: 1  # correct (paraphrased but semantically correct)
```

**Regression gate:**
- Judge-human agreement accuracy ≥ 90% on the 100-question spot-check.
- Cohen's κ ≥ 0.75 (substantial agreement).
- Any agreement drop > 3 pp = CI fail.

## Value of per-component golden sets

Scenario: Planner routing regresses from 98% to 94% after a prompt change. Consequence:
- End-to-end accuracy drops 94.37% → 92% (roughly 2.3 pp).
- If only end-to-end is measured, the regression is visible but NOT LOCALIZED.
- With Suite B: the 4 pp planner-routing regression is isolated immediately; debugging targets the planner prompt specifically.

Similarly for extraction regressions (Suite A), consolidation regressions (Suite C), judge-prompt regressions (Suite D). Per-component suites are **essential for regression attribution** in a multi-LLM pipeline.
