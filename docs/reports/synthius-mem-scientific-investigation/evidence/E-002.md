## Coverage Check (Fig. 2 bullets)

| Domain | Fig. 2 bullets | Two-layer fits? |
|---|---|---|
| Biography | 19 categories, atomic facts, confidence | YES — atomic items in array |
| Experiences | hierarchical tree, emotions, intensity, social context | YES — `parent_event_id` FK + `children` array form a tree of items in flat array |
| Preferences | polarity, strength, temporal status, original phrasing | YES |
| Social Circle | person models, closeness, trust, relationship events | YES — each person is a FactItem |
| Work | engagements, skills, tools, projects, outcomes | YES — each project is a FactItem |
| Psychometrics | 9 frameworks, normalized scores, evidence quotes | YES — each (framework,trait) is a row |

**Critical check on G-116 ("hierarchical tree"):** Hierarchical structure is achievable by FK references inside flat array — same pattern used by file-system tables, threaded comments, etc. No need for nested top-level recursive object.

**Critical check on Social Circle ("person-indexed"):** "Person-indexed" means `person_id` is the lookup key; the `facts` array is the index. Compatible.

## Reasoning chain

- Two-layer envelope draft is internally consistent across all six domains.
- Hierarchical Experiences requirement is satisfiable via parent_event_id FK + children array within a flat fact list.
- Person-indexed Social Circle requirement is satisfiable by treating each person as a FactItem keyed by person_id.
- No domain forces a non-array top-level shape.
- H-002's prediction is corroborated.
