## Per-persona run model

### 1. LoCoMo dataset structure

LoCoMo (Maharana et al. 2024, arXiv:2402.17753):
- 10 conversations
- 20 participants (2 per conversation)
- 1,813 questions total

Per conversation: 2 speakers, alternating turns, multi-session, spanning months.

### 2. First-person-run assignment

Per §4.1 verbatim:
> "Each participant gets a full pipeline run: corpus preparation, extraction across all modules, consolidation, summarization."

Interpretation: For each of the 20 participants, one independent pipeline run is executed. LoCoMo has 20 participants → **20 independent persona runs**.

For a conversation between Alice and Bob:
- Run 1 (Alice's persona): Alice's turns = first-person primary source; Bob's turns = third-party mentions (with Alice-scoped filtering).
- Run 2 (Bob's persona): Bob's turns = first-person primary source; Alice's turns = third-party mentions.

### 3. §4.1 "cross-person contamination" language

Paper verbatim:
> "Cross-person contamination would indicate a pipeline bug, not a feature."

Interpretation:
- Alice's persona must NOT have Bob's biographical facts (e.g., Bob's birthdate).
- Bob's persona must NOT have Alice's biographical facts.
- Each persona contains only its own first-person facts + filtered third-party mentions (e.g., "Bob mentioned he likes sushi" may live in Alice's Social Circle but ONLY as Bob-is-a-person-Alice-knows, not as Alice-likes-sushi).

This matches:
- **T-020** (SQLite-per-persona-file): strongest isolation, each persona is a separate DB file.
- **T-016** (no cross-persona FK): independent persona stores.
- **T-010** (dual-field refs: `_raw` + `_ref` on Social Circle references): third-party mentions have both literal text and resolved entity ID within the persona's own Social Circle.
- **G-058** (cross-persona contamination policy): filter during extraction to assign facts to correct persona.

### 4. Worked Alice/Bob example

**Source dialogue (LoCoMo-style):**
```
Alice: I graduated from MIT in 2018 with a CS degree.
Bob: Cool! I did my PhD at Stanford, wrapped up in 2020.
Alice: What was your thesis on?
Bob: NLP for healthcare. I work at a startup now doing medical NER.
Alice: Nice. I'm a senior engineer at Google in Mountain View.
```

**Run 1 — Alice's persona:**
- Biography: {degree: CS, institution: MIT, year: 2018; role: Senior Engineer, employer: Google, location: Mountain View}
- Social Circle: {person: "Bob", occupation: "PhD, NLP healthcare startup"}  ← Bob stored as a person Alice knows; Bob's biographical facts stored in Alice's SOCIAL CIRCLE, not Biography
- Work: {employer: Google, role: Senior Engineer}
- Experiences: []
- Preferences: []
- Psychometrics: scored based on Alice's turns only

**Run 2 — Bob's persona:**
- Biography: {degree: PhD, institution: Stanford, year: 2020}
- Social Circle: {person: "Alice", occupation: "Senior Engineer at Google, Mountain View"}
- Work: {employer: "startup", role: "medical NER"}
- Experiences: []
- Preferences: []
- Psychometrics: scored based on Bob's turns only

**Cross-contamination check:**
- Alice's Biography must NOT contain Bob's PhD / Stanford (correct ✓).
- Bob's Biography must NOT contain Alice's MIT / Google (correct ✓).
- Alice's Social Circle CAN contain Bob's facts as Alice's knowledge ABOUT Bob (correct ✓, per T-010 dual-field `_raw: "PhD, NLP healthcare startup"`, `_ref: Bob.person_id`).

### 5. Contrast with alternative readings

**Alternative reading A (fully-symmetric):** Both Alice and Bob's turns feed both personas.
- Consequence: Alice's persona contains "PhD Stanford 2020" in Biography — this is BOB's fact.
- Paper's "cross-person contamination would indicate a pipeline bug" explicitly RULES THIS OUT.

**Alternative reading B (single-participant per dialogue):** Only one participant per conversation gets a persona run.
- Consequence: Only 10 persona runs for LoCoMo's 10 conversations.
- Paper's "each participant gets a full pipeline run" — 20 participants → 20 runs — RULES THIS OUT.

H-114's symmetric-per-participant reading is the only one consistent with paper text.

### 6. Compatibility with T-020

T-020 SQLite-per-persona-file:
- 20 files for LoCoMo evaluation (Alice.db, Bob.db, etc.).
- Each extraction run writes to its own file.
- No cross-file joins.

This is architecturally the cleanest realization of per-persona isolation. ✓

### 7. Implications for accuracy measurement

94.37% = aggregate binary-judge accuracy across 1,813 questions.
- Each question is tagged with its target participant (whose persona it queries).
- Question about Alice's education → queries Alice.db.
- Question about Bob's occupation → queries Bob.db.

No cross-persona retrieval expected; correctness requires persona-specific retrieval. ✓
