
Postgres guarantees:
- **Atomicity**: all 6 UPSERTs commit or none do. Crash between any two UPSERTs rolls back the entire transaction via WAL recovery.
- **Isolation**: under default READ COMMITTED, concurrent retrieval reads see either all pre-batch state OR all post-batch state, never a mid-batch torn view.
- **Per-persona scope**: transaction touches only the target persona's rows (WHERE persona_id = '<uuid>'). No cross-persona FK (T-016), so no locks are taken outside this persona's row set.

## Drafted per-persona transaction (SQLite-per-persona, H-031)

```python
def consolidate_persona(persona_uuid: str, batch: ConsolidationBatch):
    path = tenant_index.resolve(persona_uuid)   # global index: uuid → path
    conn = sqlite3.connect(path, isolation_level=None)
    conn.execute("PRAGMA journal_mode=WAL")
    conn.execute("BEGIN IMMEDIATE")             # exclusive write lock on this file
    try:
        for domain in DOMAINS:
            for fact in batch[domain]:
                conn.execute(UPSERT_STMTS[domain], fact.to_row())
        conn.execute("COMMIT")
    except Exception:
        conn.execute("ROLLBACK")
        raise
    finally:
        conn.close()
```

SQLite guarantees:
- **Atomicity**: the per-persona file's WAL log ensures all 6 domain inserts commit or none do. Crash recovery replays the WAL on next open.
- **Write exclusion**: `BEGIN IMMEDIATE` takes a RESERVED lock; other writers to this persona's file wait. Readers can continue with the pre-commit snapshot (WAL mode).
- **Per-persona scope**: the entire file IS the persona; no locks cross personas. Different personas can consolidate concurrently without contention.

## Crash-recovery pseudocode

```python
def crash_recovery():
    # Postgres: automatic via WAL replay on startup.
    # Database engine handles it — no app logic needed.

    # SQLite per-persona: automatic via per-file WAL replay.
    for persona_path in scan_persona_files():
        with sqlite3.connect(persona_path) as conn:
            # Opening a file with a non-empty WAL triggers implicit recovery.
            # SQLite finishes committed transactions and discards uncommitted ones.
            conn.execute("PRAGMA wal_checkpoint(TRUNCATE)")
```

Key property: **no app-level reconciliation needed.** Both Postgres and SQLite's WAL primitives are idempotent on replay. An observer reading the store after recovery sees a consistent snapshot — either the pre-batch state (if the crash happened before COMMIT) or the post-batch state (if after).

### Failure mode coverage
