### Compatibility with Synthius-Mem's 6-parallel-extraction pattern

T-042 6-parallel-calls + T-060 strict-JSON structured output:
- LiteLLM: supports structured output via `response_format: {type: "json_schema", json_schema: ...}` on compatible models; for providers that don't natively support it, LiteLLM provides automatic fallback to tool-calling or regex validation.
- OpenRouter: passes through structured-output params where supported; falls back to JSON mode on best-effort.
- Portkey: supports virtual-key routing with per-call provider choice; structured output flows through.

**All three gateways can run the 6-parallel-call extraction pattern** because:
1. Each call is independent (no shared streaming state).
2. Concurrent requests are first-class in all 3 gateways.
3. `response_format` or equivalent is passed to the upstream provider; where unsupported, fallback to tool-use matches Anthropic's native tool-use schema.

### Overhead analysis vs 21.79 ms retrieval budget

Gateway overhead adds to LLM call latency, not retrieval. The 21.79 ms retrieval budget is unaffected by gateway choice. At the LLM call path:
- Baseline GPT-4.1-mini p50 ≈ 1,500 ms

- Percentage: 0.7-3.3% overhead → well below H-100's <10% threshold and far below the 30% "architecturally undesirable" cutoff
