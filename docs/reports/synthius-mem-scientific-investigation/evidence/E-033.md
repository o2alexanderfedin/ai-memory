## Drafted Index Plan

```sql
-- Per-domain plan: one GIN on the entire fields payload + targeted functional B-trees on hot extracted fields.

-- BIOGRAPHY
CREATE INDEX idx_bio_fields_gin ON biography USING GIN (fields jsonb_path_ops);
CREATE INDEX idx_bio_institution ON biography (persona_id, (fields->>'institution'));
CREATE INDEX idx_bio_year        ON biography (persona_id, ((fields->>'year')::int));
CREATE INDEX idx_bio_category    ON biography (persona_id, (envelope->>'category'));

-- EXPERIENCES
CREATE INDEX idx_exp_fields_gin  ON experiences USING GIN (fields jsonb_path_ops);
CREATE INDEX idx_exp_parent      ON experiences (persona_id, (fields->>'parent_event_id'));
CREATE INDEX idx_exp_date_range  ON experiences (persona_id,
  ((fields->>'start')::timestamptz), ((fields->>'end')::timestamptz));

-- PREFERENCES
CREATE INDEX idx_pref_fields_gin ON preferences USING GIN (fields jsonb_path_ops);
CREATE INDEX idx_pref_target     ON preferences (persona_id, (fields->>'target'));
CREATE INDEX idx_pref_category   ON preferences (persona_id, (fields->>'category'));

-- SOCIAL_CIRCLE
CREATE INDEX idx_soc_fields_gin  ON social_circle USING GIN (fields jsonb_path_ops);
CREATE INDEX idx_soc_names_gin   ON social_circle USING GIN ((fields->'names') jsonb_path_ops);
CREATE INDEX idx_soc_aliases_gin ON social_circle USING GIN ((fields->'aliases') jsonb_path_ops);

-- WORK
CREATE INDEX idx_work_fields_gin ON work USING GIN (fields jsonb_path_ops);
CREATE INDEX idx_work_employer   ON work (persona_id, (fields->>'employer'));

-- PSYCHOMETRICS
CREATE INDEX idx_psy_fields_gin  ON psychometrics USING GIN (fields jsonb_path_ops);
```

## Latency Arithmetic Table (commodity HW: 8-core / 16 GB, NVMe SSD, PG 16)

### Per-operation cost (cached, steady state)

| Operation | Cost | Source |
|---|---|---|
| B-tree probe (depth log2(N), cached) | log2(200K) × 50 ns ≈ **0.9 µs** | PG B-tree benchmarks |
| Functional index evaluation | +~500 ns | Expression eval overhead |
| GIN containment `@>` probe | ~**100–500 µs** | Bitmap scan, cached leaf pages |

| Query planner (parse + rewrite + plan) | ~**200–500 µs** | Simple equality planning |
| libpq marshaling (one row out) | ~**100 µs** |  |

### Hot-path query: "Where did Alice study?" (Biography lookup)

```sql
SELECT fields, envelope FROM biography
 WHERE persona_id = $1 AND fields->>'institution' = 'UCL';
```

Plan: Index Scan on `idx_bio_institution`.

| Step | Cost |
|---|---|
| Planner | ~300 µs |
| B-tree probe (2-col compound) | ~1 µs |
| Heap fetch (1–5 matching rows) | ~250 µs |
| Result serialization + marshaling | ~200 µs |
| **Total** | **~750 µs** |

**Headroom vs 21.79 ms: ~29×.** ✓

### Alternative: GIN containment query

```sql
SELECT fields, envelope FROM biography
 WHERE persona_id = $1 AND fields @> '{"institution":"UCL"}';
```

Plan: Bitmap Index Scan on `idx_bio_fields_gin` + Bitmap Heap Scan.

| Step | Cost |
|---|---|
| Planner | ~500 µs |
| GIN probe + bitmap construction | ~200 µs |
| Bitmap heap scan | ~500 µs |
| Result marshaling | ~200 µs |
| **Total** | **~1.4 ms** |

**Headroom: ~15×.** ✓

### Worst-case: multi-field conjunction with range

```sql
SELECT * FROM experiences
 WHERE persona_id = $1
   AND (fields->>'start')::timestamptz BETWEEN '2015-01-01' AND '2019-12-31';
```

B-tree range scan on `idx_exp_date_range`: ~2 µs probe + up to 20 rows fetch = ~5 ms. **Headroom: ~4×.** ✓
