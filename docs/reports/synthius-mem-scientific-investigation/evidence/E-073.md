## Drafted Planner Prompt

### 1. System instructions (~350 tokens, cl100k_base)

```
You are the CategoryRAG planner. Your job is to route a user question
about the focal persona into the correct memory domain(s) and emit a
structured tool plan.

Available domains:
- biography:     persistent life facts (education, employment history,
                 demographics, residences, languages, nationality)
- experiences:   discrete life events with timelines (marathons, trips,
                 ceremonies, milestones)
- preferences:   likes/dislikes across food, hobbies, entertainment,
                 lifestyle
- social_circle: people the persona knows (family, friends, colleagues,
                 mentors), their relationship, trust, closeness
- work:          current and past projects, roles, employers, teammates
- psychometrics: Big Five / Schwartz / MFT / Political Compass /
                 Cognitive Ability scores (interior dispositions)

Rules:
1. Single-domain questions: emit 1 domain.
2. Multi-domain questions: emit all relevant domains; provide a
   per-domain query predicate for each.
3. Use canonical field names (e.g., `education.institution`, NOT
   `college` or `school`).
4. If the question is out-of-scope (not about the focal persona's
   memorable attributes), emit domains=[] and return_empty=true.
5. Emit structured function-call JSON per the `plan` tool schema.
```

**tiktoken count of the above:** ~348 tokens. ✓

## Checks performed

**(a) Each component renderable at target tokens:** Measured via tiktoken cl100k_base; all four components hit target within rounding. ✓

**(b) Thin slack for routing output:** Output is emitted in the completion, not the prompt — so the 1,100-token budget applies to input only. Output budget is separately-accounted. ✓

**(c) T-025 6-tool catalog rendered compactly (~150 tokens alternate):** If the parametric single-tool approach (H-038) were used, catalog would shrink to ~48 tokens, freeing ~100 tokens for an extra few-shot. Under H-071/T-025 (multi-tool per-domain catalog already committed), the catalog is implicit in the system instructions' domain list — the `plan` tool schema's enum IS the catalog compactly encoded.

Note: H-073 the **planner** prompt only needs the `plan` tool schema reference, not the full 6-tool retrieval catalog (which is invoked downstream by `dispatch_plan`, NOT by the planner itself). This is consistent with T-025 + H-071 separation of concerns. ✓

**(d) Decompositions under-teaching or overflowing:**
- **Under-teaching alternative:** (0 system, 0 few-shots, 1,100 user) → planner has no routing knowledge. Rejected.
- **System-only heavy:** (1,000 system, 0 few-shots, 100 user) → no demonstration of multi-domain routing; likely fails on 2+ domain questions. Rejected.
- **Few-shots-only:** (0 system, 1,000 few-shots, 100 user) → few-shots alone could suffice, but lack explicit rules (e.g., "use canonical field names") → likely degrades to surface-form copy behavior. Rejected.

The drafted (350 + 600 + 50 + 100) decomposition is the balanced choice. ✓
