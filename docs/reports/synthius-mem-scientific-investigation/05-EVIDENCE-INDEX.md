## Notes on the evidence corpus

- **Evidence IDs track hypothesis IDs**, not theory IDs. The sequence `E-001.md` supports hypothesis `H-001`, which (when promoted) became theory `T-001`. For most entries the mapping is 1:1.
- **Some theories cite multiple evidence files** — typically the primary experiment plus the experiment that refuted the competing sibling hypothesis. These corroboration-via-refutation pairs are the strongest form of support in the corpus (e.g., T-068 cost-model triangulation cites three evidence files).
- **Every evidence file carries a peer-review note** `R-NNN` appended at the end — reviewer adjudication of the runner's PASS / FAIL / INCONCLUSIVE call. The `R-NNN` text is NOT in a separate file; it is inside the `E-NNN.md` file. See any evidence file for the `## Reviewer Adjudication (R-NNN)` section.
- **T-114 evidence (E-142.md) is coordinator-drafted** rather than sub-agent-generated because Wave 6 hit a subagent rate limit. The Coordinator adjudicated inline; see `ledger/WAVES.md` line "Wave 6 complete (2026-04-21 inline by Coordinator...)" for the rationale.
- **Refuted hypotheses have their refuting evidence captured inline in `ledger/REFUTED.md`**, not in separate files. For example, H-032 (MongoDB) is refuted in `REFUTED.md` with evidence pointers to `E-032.md` INCONCLUSIVE + `R-032.md` dominance argument.

For the full audit trail (experiment design, runner output, reviewer verdict, adjudication), follow any `T-NNN` → `E-NNN.md` link from the index above. For cross-wave navigation, see `ledger/TRACE.jsonl` which records every wave-transition event.
